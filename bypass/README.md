# bypass v2 (candidate)

Это **кандидат для репозитория**, а не готовая замена установленного скрипта.

- `bypass list`: существующие пользовательские исключения без root.
- `sudo bypass add <IP|CIDR|domain>`: создать прямой маршрут.
- `sudo bypass del <IP|CIDR|domain>`: удалить исключение.
- `sudo bypass restore`: обновить DNS и перепроверить исключения.

Конфигурация исключений: `/etc/bypass-routes.json`; необязательная политика: `/etc/bypass-policy.json`; журнал владения маршрутами и правилами: `/var/lib/bypass/managed-routes.json`. Все они **локальные** и не должны попасть в Git.

Определяет шлюз по наилучшему `default` в таблице `main`. Отказывается работать при отсутствии шлюза, неоднозначном выборе или известных именах VPN-интерфейсов. Выбор по имени интерфейса — эвристика, не гарантия физического устройства.

Использует маршрут в `main` и таблице Outline (по умолчанию `7113`) и правило `priority 800`, существующую схему конкретной системы. Не гарантирует обход любого VPN, fwmark, отдельного SOCKS/HTTP-прокси или firewall/NAT.

## Безопасность и миграция

**Не устанавливать автоматически поверх старой версии.** Действующая версия создала правила без реестра владения. Новая утилита намеренно распознаёт такие существующие маршруты и правила как чужие и отказывается их заменять/удалять. Нужна отдельная осознанная миграция после инвентаризации существующих объектов. Если маршрут или правило изменены извне, утилита тоже откажется их удалять.

Защита активных VPN-серверов обнаруживает только IPv4-адреса из `--remote` процессов OpenVPN. Дополнительные запреты указываются в `protected_networks` и `protected_endpoints`. Пустая необязательная политика не защищает неизвестные корпоративные подсети. Если эти сети важны, укажи их локально.

При сбое между изменением системного маршрута и записью реестра возможен неполный результат; при недоступности сети после создания частичных маршрутов также потребуется диагностика. По этой причине сначала нужны тестирование в изолированной сетевой среде и отдельная миграция существующих исключений.

## Тесты без root

Из директории, где лежат `bypass-v2` и `test_bypass_v2.py`:

```bash
python3 test_bypass_v2.py
```

Тесты используют заглушки системных команд и не изменяют реальные маршруты.
