# tunnels

`tunnels` хранит именованные локальные пробросы SSH и запускает их как `ssh -N -L`. Отдельный туннель — одна запись в конфиге и один процесс `ssh`.

Утилита не поднимает SSH-сервер, не создаёт ключи и не правит `~/.ssh/config`. Пароль у SSH она спросить не может: в команде стоит `BatchMode=yes`. Нужен ключ или уже открытый ssh-agent. Порт, `ProxyJump` и файл ключа задаются алиасом в `~/.ssh/config`, потому что поле SSH здесь — один аргумент без пробелов и без ведущего `-`.

Общая установка: [INSTALLATION.md](../INSTALLATION.md). Восстановление компьютера: [docs/recovery.md](../docs/recovery.md). Остальные утилиты: [README.md](../README.md).

## Что делает

Для записи с именем `db` запускается такая команда:

```text
ssh -N -T -o ExitOnForwardFailure=yes -o BatchMode=yes -L 127.0.0.1:5432:127.0.0.1:5432 db-jump
```

`-N` означает, что удалённая оболочка не открывается. `-T` отключает псевдотерминал. `ExitOnForwardFailure=yes` завершает `ssh`, если локальный порт занять не удалось. Процесс запускается в новой сессии, поэтому закрытие терминала его не убивает. Стандартный вывод отбрасывается. Ошибки `ssh` пишутся в файл журнала туннеля; при каждом `start` этот файл создаётся заново, предыдущий текст того же имени стирается.

`ServerAliveInterval` и свой таймаут разрыва утилита не задаёт. Когда TCP-сессия SSH рвётся, процесс `ssh` обычно завершается сам, по обычным правилам клиента OpenSSH. Файл PID при этом остаётся, пока следующая команда `status`, `stop`, `start`, `del` или `rename` его не проверит. Живым туннель считается только если PID из файла существует и его командная строка в `/proc` — это `ssh` с теми же аргументами, что собраны из конфига.

## Установка

```bash
cd ~/pets/linux-toolbox
./install.sh check tunnels
./install.sh install tunnels
```

Из каталога утилиты: `./install.sh` проверяет, `./install.sh --install` ставит.

Файл копируется в `~/.local/bin/tunnels` с правами `755`. `sudo` установщик для этой утилиты не вызывает. Конфиг и каталог состояния не создаются, пока вы сами не добавите туннель.

Проверьте, что каталог есть в `PATH`:

```bash
export PATH="$HOME/.local/bin:$PATH"
command -v tunnels
```

Нужны Python 3 и клиент OpenSSH (`ssh`). Если `ssh` или `python3` нет, `check` и установка завершаются с кодом 1.

Повторная установка:

```bash
./install.sh install tunnels --replace
```

Предыдущая программа сохраняется рядом как `~/.local/bin/tunnels.bak.ГГГГММДДЧЧММСС`. Уже запущенные процессы `ssh` замена скрипта не останавливает: после замены это по-прежнему обычный `ssh`, а не процесс Python.

## Настройка с нуля

Интерактивно утилита спрашивает имя, SSH-хост, локальный адрес, локальный порт, адрес сервиса со стороны сервера и удалённый порт. Для скрипта и для истории в шелле удобнее передать всё флагами сразу. Если флаг опущен, программа всё равно спрашивает это поле в терминале. Пустой ответ в вопросе означает значение по умолчанию или прежнее значение при `edit`. В неинтерактивном запуске без полного набора флагов ввод закончится сразу, программа напечатает `Отменено` и выйдет с кодом 130.

Сначала алиас в `~/.ssh/config`:

```text
Host db-jump
    HostName server.example
    User deploy
    IdentityFile ~/.ssh/id_ed25519
```

Затем запись туннеля. Локальный адрес по умолчанию `127.0.0.1`. Адрес сервиса на дальней стороне тоже по умолчанию `127.0.0.1`: это сервис на самом SSH-сервере, а не на вашей машине.

```bash
tunnels add db \
  --ssh db-jump \
  --bind 127.0.0.1 \
  --local-port 5432 \
  --remote-host 127.0.0.1 \
  --remote-port 5432
```

Имя: латиница, цифры, `_` и `-`, первый символ — буква или цифра. Регистр различается. `db` и `DB` — разные туннели.

Порты — целые от 1 до 65535. SSH-хост — один фрагмент без пробелов и без ведущего дефиса. Адреса тоже без пробелов. Отдельной проверки, что это именно IP, нет: неверное значение всплывёт при запуске `ssh`. Если в адресе есть двоеточие (IPv6), утилита сама ставит квадратные скобки в аргументе `-L`.

Появится файл `~/.config/tunnels/config.json`:

```json
{
  "db": {
    "ssh": "db-jump",
    "bind": "127.0.0.1",
    "local_port": 5432,
    "remote_host": "127.0.0.1",
    "remote_port": 5432
  }
}
```

Каталог создаётся с режимом `700`, файл — `600`. Внутри репозитория файл с именем `config.json` игнорируется Git, но этот конфиг и так лежит в домашнем каталоге. Копировать его в репозиторий не нужно: в нём имена хостов и пользователей.

`tunnels` через `sudo` запускать не стоит. Конфиг, PID и процесс окажутся у root и будут пользоваться ключами root.

## Команды

`tunnels` без аргументов, `tunnels list` и `tunnels status` вызывают один и тот же вывод. Отдельной глубокой проверки `status` нет.

| Команда | Аргументы | Поведение |
| --- | --- | --- |
| `tunnels`, `tunnels list`, `tunnels status` | нет | Имя, признак процесса, локальный и дальний адрес, SSH-назначение. |
| `tunnels add` | `[имя]` и флаги ниже | Создаёт запись. Если имя уже есть: `туннель … уже существует; используйте edit`. |
| `tunnels edit` | `[имя]` и флаги ниже | Меняет запись. Для неинтерактивного вызова передайте все поля, которые не хотите вводить вручную. Работающий туннель править нельзя. |
| `tunnels start` | имя или `all` | Запускает один туннель или все по алфавиту. |
| `tunnels stop` | имя или `all` | Посылает `SIGTERM` и сразу удаляет файл PID. |
| `tunnels del` | имя | Удаляет запись. `del all` запрещён: `del all не поддерживается`. Сначала остановите туннель. |
| `tunnels rename` | старое имя, новое имя | Переименовывает запись. Запущенный туннель переименовать нельзя. |

Флаги `add` и `edit`:

| Флаг | Смысл | Если спросить в терминале и нажать Enter |
| --- | --- | --- |
| `--ssh` | Алиас из `~/.ssh/config` или `user@server` | Обязательное поле, пустого значения по умолчанию нет. |
| `--bind` | Локальный адрес прослушивания | `127.0.0.1`, а при `edit` — прежний адрес. |
| `--local-port` | Локальный порт | Обязательное поле при создании. При `edit` Enter сохраняет прежний порт. |
| `--remote-host` | Куда подключаться уже со стороны SSH-сервера | `127.0.0.1` или прежнее значение. |
| `--remote-port` | Порт на дальней стороне | Обязательное поле при создании. При `edit` Enter сохраняет прежний порт. |

Имя можно не передавать только в интерактивном `add` и `edit`: программа его спросит.

`start` считает туннель уже запущенным, если PID живой и командная строка совпала. Повторный `start` тогда печатает `уже запущен` и второй процесс не создаёт.

Новый процесс проверяется до 10 секунд: утилита пытается открыть TCP на локальный порт. Для bind `0.0.0.0`, `::` и `*` проверка идёт на `127.0.0.1`. Успех значит, что локальный порт принял соединение. Это не запрос к удалённому приложению и не гарантия, что дальний сервис ответил.

Если `ssh` завершился в эти 10 секунд, файл PID удаляется, в stderr попадает текст журнала и программа выходит с ошибкой. Если за 10 секунд порт ещё не открылся, процесс остаётся, код выхода `0`, а в stdout написано, что SSH ещё подключается, с путём к журналу. Так бывает при медленном `ProxyJump`. Дальше смотрите `tunnels status` и журнал.

`start all` идёт по именам по алфавиту и останавливается на первой ошибке. Туннели раньше этого имени в списке уже могут быть запущены.

`stop` не ждёт завершения процесса. Он удаляет PID сразу после `SIGTERM`. `status` после этого показывает туннель выключенным, даже если `ssh` ещё на мгновение жив. Следующий `start` может успеть поднять второй процесс. Для обычной остановки это почти незаметно; если порт ещё занят, новый `start` упрётся в `ExitOnForwardFailure` и покажет журнал.

`stop` для уже выключенного туннеля печатает `не запущен`, удаляет устаревший PID и завершается успешно.

`rename` переносит запись в конфиге и удаляет старый файл PID. Файл журнала под старым именем не переименовывается и не удаляется. Новый туннель сам не запускается.

`del` удаляет запись и PID. Журнал тоже остаётся.

Ctrl+C или конец ввода во время вопроса дают `Отменено` и код 130.

## Примеры

Создать, запустить, посмотреть, остановить:

```bash
tunnels add db \
  --ssh db-jump \
  --bind 127.0.0.1 \
  --local-port 5432 \
  --remote-host 127.0.0.1 \
  --remote-port 5432
tunnels start db
tunnels status
tunnels stop db
```

Несколько штук:

```bash
tunnels start all
tunnels stop all
```

Изменить порт. Сначала остановка, затем все поля, чтобы команда не задавала вопросы:

```bash
tunnels stop db
tunnels edit db \
  --ssh db-jump \
  --bind 127.0.0.1 \
  --local-port 5433 \
  --remote-host 127.0.0.1 \
  --remote-port 5432
tunnels start db
```

Переименовать выключенный туннель и удалить:

```bash
tunnels stop db
tunnels rename db db-local
tunnels del db-local
```

Интерактивное создание — просто `tunnels add`. Enter на вопросе про локальный адрес и дальний адрес принимает `127.0.0.1`.

Если нужен сервис не на самом SSH-сервере, а в сети за ним, `--remote-host` — это адрес с точки зрения SSH-сервера, например `10.0.0.15`.

## Файлы

Переменные `XDG_CONFIG_HOME` и `XDG_STATE_HOME` учитываются. Без них пути такие:

| Путь | Содержание |
| --- | --- |
| `~/.local/bin/tunnels` | Программа. |
| `~/.local/bin/tunnels.bak.*` | Копии, которые делает `--replace`. |
| `~/.config/tunnels/config.json` | Все туннели. Каталог `700`, файл `600`. |
| `~/.local/state/tunnels/<имя>.pid` | PID последнего запуска. Каталог `700`. Наличие файла само по себе не означает, что туннель жив. |
| `~/.local/state/tunnels/<имя>.log` | stderr последнего `ssh`. При каждом `start` файл обрезается. |

В конфиге у каждой записи пять полей: `ssh`, `bind`, `local_port`, `remote_host`, `remote_port`. Если править JSON руками и удалить поле, `start` упадёт с исключением Python, а не с обычным текстом `Ошибка:`. Запущенный туннель руками в этом файле не меняют: `status` сравнивает процесс с новым конфигом, может показать его выключенным и позволить `start` поднять второй `ssh`.

Журналы и PID в Git не класть. После `rename` и `del` старый `.log` может остаться на диске.

## Права и sudo

`sudo` не нужен и вреден: сменится домашний каталог, а значит конфиг, состояние и ключи SSH.

Конфиг доступен только пользователю (`600`). В нём нет паролей, но есть имена серверов и логины. Ключи остаются в `~/.ssh` с обычными правами OpenSSH. Утилита их не копирует.

Локальный порт слушает тот адрес, который записан в `bind`. Значение по умолчанию `127.0.0.1` принимает соединения только с этой машины. `0.0.0.0`, адрес локальной сети или `::` открывают порт для других хостов. Пароля на этом порту нет: кто смог открыть TCP, пользуется пробросом с правами вашего SSH. Для личного проброса оставляйте `127.0.0.1`.

Проверка при старте для `0.0.0.0` всё равно подключается к `127.0.0.1`. Успех этой проверки не означает, что порт закрыт от сети.

## Проверка

Диагностика, процессы не останавливает и не создаёт:

```bash
tunnels status
cat ~/.local/state/tunnels/db.pid
tr '\0' ' ' < /proc/$(cat ~/.local/state/tunnels/db.pid)/cmdline
tail -n 50 ~/.local/state/tunnels/db.log
ss -ltn 'sport = :5432'
```

`status` показывает `● работает` только когда PID из файла принадлежит `ssh` с аргументами из конфига. Иначе строка `○ выключен`, даже если файл PID ещё лежит. Если `cat` по `/proc/.../cmdline` не открывается, процесса нет. `tunnels stop db` в этом случае просто убирает PID.

`ss` показывает, слушается ли локальный порт. Утилита заранее не проверяет, что два туннеля выбрали один и тот же порт. Второй `start` завершится ошибкой SSH, журнал будет в `.log`.

Если статус «работает», а приложение по локальному порту не отвечает, процесс жив, но дальний сервис может быть недоступен. Смотрите журнал. Команда старта это не отличает: ей достаточно открытого локального порта.

Ручная проверка с вашей машины, без новых туннелей:

```bash
ssh -N -T -o ExitOnForwardFailure=yes -o BatchMode=yes \
  -L 127.0.0.1:5432:127.0.0.1:5432 db-jump
```

Это уже настоящий SSH-сеанс в текущем терминале. Остановите его Ctrl+C, прежде чем вызывать `tunnels start` на тот же порт.

## Обновление

```bash
cd ~/pets/linux-toolbox
git pull
./install.sh check tunnels
./install.sh install tunnels --replace
```

Конфиг, PID и журналы установщик не меняет. Работающие пробросы продолжают идти старыми процессами `ssh`. Новые флаги программы вступят в силу при следующем `start`.

## Отключение и удаление

Остановка не удаляет записи:

```bash
tunnels stop all
```

Полное удаление программы и, если туннели больше не нужны, данных:

```bash
tunnels stop all
rm -f ~/.local/bin/tunnels
rm -f ~/.local/bin/tunnels.bak.*
rm -rf ~/.config/tunnels ~/.local/state/tunnels
```

Если удалить только программу и оставить процессы, `ssh` продолжит держать порты. Сначала `tunnels stop all`. Конфиг стоит сохранить перед переустановкой системы, даже если программу вы снимаете. Список файлов: [docs/recovery.md](../docs/recovery.md).

Systemd-юнита у `tunnels` нет. После выхода из системы и при следующей загрузке туннели сами не поднимаются: их снова запускают `tunnels start` или `tunnels start all`.

## Ошибки и диагностика

| Что видно | Что сделать |
| --- | --- |
| `command not found: tunnels` | В `PATH` нет `~/.local/bin`, либо программа не ставилась. `command -v tunnels`. |
| `туннель … уже существует; используйте edit` | Имя занято. Другое имя или `edit`. |
| `туннель … не найден` | Имя не совпало с ключом в конфиге, учтите регистр. `tunnels list`. |
| `имя: только латинские буквы, цифры, _ и -` | Имя пустое, начинается с `_` или `-`, либо содержит другой символ. |
| `SSH-хост должен быть одним аргументом и не начинаться с -` | Порт и ключ уберите в `~/.ssh/config`, в `--ssh` оставьте алиас или `user@host`. |
| `сначала остановите работающий туннель` или `сначала остановите туннель` | `edit`, `rename` и `del` требуют остановки. |
| `del all не поддерживается` | Удаляйте по одному имени. |
| `SSH завершился` и текст журнала | Откройте `~/.local/state/tunnels/<имя>.log`. Частые причины: нет ключа при `BatchMode`, занятый локальный порт, неверный алиас, отказ дальнего порта ещё на этапе `ExitOnForwardFailure`. |
| `SSH ещё подключается` | Подождите и снова выполните `tunnels status`. Если процесс исчез, читайте журнал. |
| В статусе «выключен», а файл PID есть | Процесса нет или его командная строка не совпала с конфигом. `tunnels stop <имя>` убирает файл. |
| В статусе «работает», порт не служит | Смотрите `ss` и журнал. Процесс `ssh` жив, удалённое приложение может быть недоступно. |
| `Отменено`, код 130 | Прерван вопрос или Ctrl+C. Если это случилось в `start`, проверьте `tunnels status`: процесс мог уже стартовать. |
| Два туннеля, второй не поднимается | Разведите `--local-port`. Утилита пересечение портов заранее не ищет. |

Поиск PID, который «есть», но туннеля нет:

```bash
tunnels status
pid=$(cat ~/.local/state/tunnels/db.pid 2>/dev/null || true)
echo "pid file: ${pid:-нет}"
if [[ -n "${pid}" ]]; then
  tr '\0' ' ' < "/proc/${pid}/cmdline" || echo "процесса ${pid} нет"
fi
tail -n 50 ~/.local/state/tunnels/db.log
```

Первая команда безопасна. `tail` только читает журнал.

## Ограничения и безопасность

- Проброс только локальный (`-L`). Удалённый `-R` и динамический `-D` не поддерживаются.
- Один процесс на имя, без перезапуска по расписанию и без systemd.
- Нет собственных keepalive. Долгий обрыв виден как завершившийся `ssh` и статус «выключен» при ещё лежащем PID, пока вы не вызовете `status` или `stop`.
- `stop` не дожидается конца процесса.
- `list` и `status` ничем не отличаются и не опрашивают дальний сервис.
- Журнал перезаписывается при каждом старте и может содержать имена хостов из сообщений `ssh`. Пароль туда не попадает: интерактивный пароль отключён.
- Bind на нелокальный адрес публикует проброс в сети без дополнительной аутентификации на этом порту.
- Конфиг и `~/.ssh` нужны вместе. Репозиторий хранит только программу.
